# Sync Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Music and audiobooks dropped into a Mac folder appear in the phone's Listen library (and disappear when deleted), one way, over syncd, with no UI.

**Architecture:** syncd (Nico's repo) gets opt-in switches: pull-only, atomic writes, incremental pull with a full-wipe guard, blob reclaim, settled-only publish, a status file and better logs. This repo vendors syncd as a git submodule at `vendor/syncd`, deploys it to the phone as the `calm-syncd` systemd service, and installs it on the Mac as a launchd agent. The daemon watches `~/Music` to rescan, and reads syncd's status file so a running sync blanks the screen instead of suspending.

**Tech Stack:** Node 26 (`node:test`, `fs.watch` recursive), syncd deps (`hyperdrive` 13, `corestore` 7, `hyperswarm` 4, `localdrive`, `mirror-drive` 1.14), systemd, launchd, rsync.

**Spec:** `docs/superpowers/specs/2026-11-08-sync-design.md`

## Global Constraints

- Daemon: plain `.mjs`, zero npm dependencies, listens on `127.0.0.1` only. syncd runs as its own process, never inside the daemon.
- The shell does not change: no new SSE event, no new action, no sync UI.
- syncd: every new behaviour is behind an env switch; with none set, syncd behaves as today (two-way, non-atomic). Its tests run with `npm test` (`node --test`) and need no network.
- syncd env switches (exact names): `PUSH` (`0` = don't publish), `ATOMIC` (`1`), `WIPE_GUARD` (`1`), `SETTLE_MS` (ms, default `0`), `STATUS_FILE` (path, default unset).
- Phone paths: code `/opt/calm-syncd`, storage `/home/user/.local/share/syncd`, config `/home/user/.config/syncd/env` (holds `PEER_KEY=`), status `/home/user/.local/state/syncd/status.json`, folder `/home/user/Music`. Unit: `calm-syncd`, logs via `journalctl -u calm-syncd`.
- Mac paths: folder `~/Phone/Music` (overridable), app `~/Library/Application Support/syncd/app`, storage `~/Library/Application Support/syncd/storage`, log `~/Library/Logs/syncd.log`, launchd label `dev.rebelphone.syncd`, `SETTLE_MS=10000`.
- "Syncing" for the daemon = status file JSON has `"syncing": true` and its mtime is ≤ 120 000 ms old.
- Full-wipe guard: refuse a pull whose result would leave the folder with zero files while it has ≥ 1 now.
- Config files comment-free (JSON, unit file, plist). Commits: conventional, lowercase. Never push (this repo or syncd) without asking Nico.
- Verify on the phone, not just the Mac (`AGENTS.md`).

## Review Focus

- First sync over the phone's current test files: the guard must **allow** it (result is non-empty) and replace them. → test in Task 2.
- File names with spaces, accents, dashes and quotes (`Arvo Pärt — Spiegel "live".mp3`) and nested folders sync, and deleting a whole album folder removes its files. → test in Task 2.
- A file replaced on the Mac with new content under the same name: the phone gets the new bytes and the old blob is reclaimed on both sides. → tests in Tasks 2 and 3.
- Phone loses power mid-download: leftover `*.localdrive.tmp` files in `~/Music` are removed at the next start, never kept forever. → test in Task 2.
- syncd crashes or stalls with `"syncing": true` on disk: the daemon stops counting it after 120 s, so the phone can still suspend. → test in Task 6.

### Task 2: Pull: atomic writes, incremental by version, full-wipe guard, reclaim, tmp cleanup

**Files:**
- Create: `test/pull.test.mjs`
- Modify: `lib.mjs`

**Interfaces:**
- Consumes: `log`, test helpers (Task 1).
- Produces:
  - `openFolder(dir: string, { atomic: boolean }): Localdrive` — `new Localdrive(dir, { atomic })`.
  - `removeStaleTmp(dir: string): Promise<number>` — deletes every `*.localdrive.tmp` under `dir` (recursive), returns how many.
  - `reclaim(drive: Hyperdrive, fromVersion: number): Promise<number>` — for every entry deleted or whose blob changed between `fromVersion` and `drive.version` (via `drive.diff(fromVersion)`), `drive.blobs.clear(oldEntry.value.blob)`; returns the number cleared. `fromVersion === 0` → `0`.
  - `pull({ drive: Hyperdrive, folder: Localdrive, fromVersion: number | null, wipeGuard: boolean, onDownload?: () => void }): Promise<{ version: number, count: { add, change, remove }, refused: boolean }>`
    - `fromVersion === null` → full mirror (`drive.mirror(folder)`); else `entries` = keys from `drive.diff(fromVersion)` and `drive.mirror(folder, { entries })`, so unchanged files are never read.
    - With `wipeGuard`, first a `dryRun` mirror with the same options; if the folder has ≥ 1 file and `files − remove + add === 0`, return `refused: true` without writing (log `pull refused: would leave <folder> empty`).
    - After a non-refused mirror: `reclaim(drive, fromVersion ?? 0)`.
    - `onDownload` is called on every block the drive's blobs core downloads (`drive.blobs.core.on('download', …)`), removed when the pull ends.
  - `loadPulled(storage: string, key: string): Promise<number | null>` / `savePulled(storage: string, key: string, version: number): Promise<void>` — `<storage>/pulled.json` = `{ "key": "<hex>", "version": N }`; a different key or missing/invalid file → `null`. Atomic write (tmp + rename).

- [ ] **Step 1: Failing tests** in `test/pull.test.mjs` (the "Mac drive" is a Hyperdrive in a `tmpStore`, filled with `drive.put`; no swarm):
  - **first full pull:** drive has `album/01 Intro.mp3`, `Arvo Pärt — Spiegel "live".mp3`; folder already has `old.mp3` (phone test files) → with `wipeGuard: true`, `refused === false`, folder files equal exactly the two drive keys.
  - **incremental add/change/delete:** after a pull at version v, `put('album/02.mp3')`, overwrite `album/01 Intro.mp3` with new bytes, `del('Arvo…mp3')` → `pull({ fromVersion: v })` gives `count` `{ add: 1, change: 1, remove: 1 }`, folder contents match, and the new bytes of `01 Intro.mp3` are on disk.
  - **folder delete:** deleting both keys under `album/` removes both files from the folder.
  - **guard:** delete every key, then pull with `wipeGuard: true` → `refused: true`, folder untouched; same with `wipeGuard: false` → folder empty.
  - **reclaim:** after the change+delete pull, `await drive.blobs.core.has(oldBlob.blockOffset) === false` for the replaced and the deleted file's old blobs; the current file's blob is still present.
  - **atomic:** with `openFolder(dir, { atomic: true })`, during a pull of a 5 MB file no file named `big.mp3` exists until it is complete (check: after pull, `big.mp3` size is 5 MB and no `*.localdrive.tmp` remain).
  - **tmp cleanup:** folder with `a/x.mp3.0.localdrive.tmp` and `y.mp3` → `removeStaleTmp` returns 1, `y.mp3` stays.
  - **pulled state:** `savePulled(dir, 'aa', 7)` then `loadPulled(dir, 'aa') === 7`, `loadPulled(dir, 'bb') === null`, `loadPulled(emptyDir, 'aa') === null`.
