# Listen Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Replace the fake Music screen with **Listen**: the daemon plays every audio file in `~/Music` through mpv, remembers each file's position, keeps the phone awake while playing, and the shell shows layout A on a cream paper background.

**Architecture:** New daemon modules under `daemon/listen/` (library scan, JSON store, mpv IPC client, player logic) plus small `daemon/power.mjs`, `daemon/input.mjs`, `daemon/backlight.mjs`, `daemon/audio.mjs`; `server.mjs` wires them into the existing SSE + `/actions/*` contract. The shell gets `useListen()` / `useLibrary()` hooks and a `Listen` screen. Pure logic is unit-tested with `node:test`; mpv and the phone are checked with real runs.

**Tech Stack:** Node 26 (`node:test`, `node:net`, `child_process`), mpv 0.41 JSON IPC, ffprobe, PulseAudio (`pactl`), React 19 + Vite, TypeScript.

**Spec:** `docs/superpowers/specs/2026-11-07-listen-design.md`

## Global Constraints

- Daemon: plain `.mjs`, zero npm dependencies, listens on `127.0.0.1` only.
- Shell never touches the system: only `/events` (SSE) and `POST /actions/*`.
- Every new env var is documented in `docs/architecture.md` with its default; every event and action in its contract tables.
- Defaults: `MUSIC_DIR=/home/user/Music`, `STATE_FILE=$HOME/.local/state/calm/listen.json`, `MPV_CMD=mpv`, `FFPROBE_CMD=ffprobe`.
- State file never inside `/opt/calm-daemon` (deploy runs `rsync --delete` there).
- After any restart Listen is **paused**; it never starts playing by itself.
- "Next" = next file by path, natural order (`Intl.Collator(undefined, { numeric: true, sensitivity: 'base' })`); after the last file, stop.
- Advance/⏭ start point: saved position if duration > 1200 s, else 0. Tap/▶ always resume the saved position. A file that reached its end is saved at 0.
- Skip back = 30 s, clamped at 0. Position saved every 5 s while playing and on pause, seek, file change, SIGTERM.
- Audio server on the phone is **PulseAudio** (autospawned), not PipeWire; its default sink is the snd_aloop loopback (no sound). Always choose the sink explicitly: `alsa_output.platform-sound.HiFi__Speaker__sink`, or `alsa_output.platform-sound.HiFi__Headphones__sink` when the jack is in. (Spec said `wpctl`; `pactl` replaces it because of this finding.)
- No badges, toasts or animation. Errors are one muted line, cleared after 5 s.
- Shell design: 432×912 CSS px, no hover. Commits: conventional, lowercase.

## Review Focus

- File names with spaces, accents, dashes and quotes (`Arvo Pärt — Spiegel "live".mp3`) play: ids go to mpv as JSON IPC args, never through a shell. → test in Task 3.
- A `loadfile` replacing a playing file emits `end-file` with reason `stop`; only `eof` advances and only `error` skips, otherwise rapid taps would skip files. → test in Task 4.
- The current file is deleted between scans: no crash; `current` falls back to the first file by display order, paused. → test in Task 4.
- `seek` with a negative, NaN, string or beyond-duration value: strings/NaN get 400, numbers are clamped to `[0, duration]`. → test in Task 5.
- mpv dies mid-play: it is restarted and the player comes back paused at the last saved position. → test in Task 4 (fake mpv emits `exit`).

### Task 3: mpv IPC client and ffprobe

**Interfaces:**

### Task 4: Player

**Files:**
- Create: `daemon/listen/player.mjs`, `daemon/listen/player.test.mjs`

**Interfaces:**
- Consumes: Task 1 library functions, Task 2 store, Task 3 `Mpv` interface and `probe`.
- Produces: `createPlayer({ musicDir, store, mpv, probe, publish, now = Date.now, setSink })` returning:
  - `init(): Promise<void>` — load store, scan, publish both events; `current` = stored id if still present, else first in display order; paused.
  - `rescan(): Promise<void>`, `play(id?: string): Promise<void>` (`'resume'`), `pause()`, `seek(to: number)` (clamped to `[0, duration]`), `back()` (−30), `restart()`, `next()` (`'advance'`), `isPlaying(): boolean`, `has(id): boolean`, `onHeadphones(inserted: boolean)` (sets sink via `setSink`; `false` pauses), `flush(): Promise<void>` (save now).
  - `publish('listen', { current: { id, title, folder, duration } | null, playing: boolean, position: number, positionAt: number, error: string | null })`
  - `publish('library', Array<{ id, title, folder, duration, position, lastPlayed }>)` in `displayOrder`.
- Behaviour pinned here: scans call `probe` only for ids whose `store.data.probes[id]` is missing or has a different `size`/`mtimeMs` (test: second `rescan()` with unchanged files calls `probe` 0 times); ids gone from disk are dropped from `files` and `probes`; play sets `lastPlayed = now()` and re-publishes `library`; `loadfile` with `start=<startPosition>` then unpause; `end-file` `eof` → save position 0 for that file, then `next` (`advance`) or stop paused at end of list; `end-file` `error` → `error = 'can't play <title>'`, log, then `next`; error cleared (publish `null`) after 5 s; `stop`/`redirect` ignored; save every 5 s while playing; `'exit'` from mpv → `playing = false`, publish, and after mpv restarts, reload current paused at saved position; `listen` re-published on state change and at most every 5 s while playing.
